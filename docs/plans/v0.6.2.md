# Plan v0.6.2 : code-barres et photo d'étiquette

**But** : Ambroise ajoute un produit emballé sans rien taper. Il scanne le code-barres ; si le produit est connu (chez lui ou sur Open Food Facts), les valeurs pour 100 g arrivent toutes seules. Sinon, il photographie l'étiquette et Fonte lit les valeurs sur le téléphone. Dans tous les cas, il vérifie avant d'enregistrer.

## Décisions

- **Ordre de recherche** : d'abord ses aliments et le catalogue (un produit déjà scanné est retrouvé tout de suite), puis Open Food Facts, puis la photo de l'étiquette si le produit est inconnu ou incomplet.
- **Scan en direct** avec la caméra arrière. `BarcodeDetector` du navigateur quand il existe (Chrome sur Android), sinon le même standard en bibliothèque (`barcode-detector`, lecteur zxing en WebAssembly, chargé seulement à ce moment-là). Toujours possible : saisir les chiffres, ou prendre le code en photo.
- **Open Food Facts interrogé depuis le serveur** : seul le code-barres part, jamais qui scanne ni son adresse IP. Délai de 5 s, en-tête `User-Agent` au nom de Fonte comme le demande Open Food Facts. Valeurs reprises pour 100 g (énergie en kcal, ou kJ ÷ 4,184), portion si elle est indiquée.
- **Photo de l'étiquette lue sur le téléphone, sans IA** : Tesseract.js dans un Web Worker, français. La photo n'est ni envoyée ni gardée. Le moteur (`parseNutritionLabel`) cherche les lignes Énergie, Matières grasses, Glucides, Protéines (et Sucres, Sel, Fibres pour plus tard), première colonne = pour 100 g.
- **Vérification obligatoire** : les valeurs trouvées préremplissent le formulaire d'aliment, avec leur source. Rien n'est enregistré sans un tap.
- **Le code-barres reste sur l'aliment** (`foods.barcode`, colonne déjà là) ; un index unique par personne évite les doublons.
- **Fichiers servis par Fonte** : le lecteur zxing, le moteur Tesseract et les données de langue sont copiés dans `public/scan/` au build (non versionnés). Aucun CDN tiers à l'exécution.
- **Sécurité** : `Permissions-Policy` passe à `camera=(self)` ; la CSP ajoute `'wasm-unsafe-eval'` (compiler du WebAssembly, rien d'autre). Les fichiers de `public/scan/` sortent du proxy (fichiers statiques, rien de personnel).

## Dépendances ajoutées (raison écrite)

- `tesseract.js` : lecture de texte sur le téléphone, sans IA ni serveur, demandée par la spécification. Chargée seulement quand on photographie une étiquette.
- `barcode-detector` : Safari sur iPhone n'a pas `BarcodeDetector`. Cette bibliothèque reproduit l'API standard ; le jour où Safari l'aura, il suffira de la retirer.
- `@tesseract.js-data/fra` (développement seulement) : les données de langue française, copiées au build pour ne dépendre d'aucun CDN.

## Étapes

1. **Moteur** : `isValidBarcode` (clé de contrôle EAN-8, EAN-13, UPC-A), `parseNutritionLabel`, conversion d'un produit Open Food Facts. Tests.
2. **Schéma** : index unique `(user_id, barcode)` sur les aliments non archivés. Tests RLS.
3. **Code-barres** : écran de scan, recherche (soi, catalogue, Open Food Facts), écran de vérification, aliment enregistré avec son code.
4. **Étiquette** : photo, lecture sur le téléphone, formulaire prérempli.
5. **Vérification** : captures 375 et 1440 px, `get_advisors`, revue, PR.
