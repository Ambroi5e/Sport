# Plan v1.0 : audit, tests de bout en bout, mise en production

**But** : pouvoir ouvrir Fonte à Ambroise et à ses amis en confiance. La v1.0 n'ajoute pas de fonctionnalité : elle vérifie.

La v1.0 se fait en trois PR.

## 1. Garde-fous (cette PR)

- **Sécurité du schéma entier** (`supabase/tests/schema-securite.test.ts`) : sept tests qui portent sur toutes les tables et fonctions à la fois, donc aussi sur celles des versions futures. Aucune politique ouverte au visiteur, aucune politique `true`, chaque politique s'appuie sur l'identité connectée, chaque fonction `SECURITY DEFINER` fixe un `search_path` vide, chaque table a une clé primaire, chaque table à `user_id` part en cascade avec le compte, aucune vue ne contourne la RLS. Vérifié qu'ils échouent tous sur un schéma volontairement fautif.
- **Écrans** (`e2e/apercu.spec.ts`, Playwright) : les 90 écrans de l'aperçu, à 375 et 1440 px. Chacun s'affiche avec son titre, sans erreur console, sans défilement horizontal, avec sa flèche retour s'il n'est pas un onglet racine. Lancé en CI.

## 2. Parcours connectés

- Tests de bout en bout avec un vrai compte sur une base de test : inscription sur invitation, première séance, repas noté, export, suppression du compte, cloisonnement entre deux comptes dans le navigateur.
- Demande une base Supabase jetable (stack locale ou projet de test) : à décider avec Ambroise, car un second projet Supabase gratuit ou Docker en CI changent le coût et la durée des tests.

## 3. Mise en production

- `audit/checklist-web.md` repris ligne par ligne (Lighthouse mobile, contraste, liens, métadonnées).
- Revue de sécurité finale, `get_advisors`, fichiers `pending-destructive` validés par Ambroise et appliqués.
- Fusion des PR dans l'ordre, puis feu vert d'Ambroise pour la production.
